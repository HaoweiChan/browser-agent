# Support matrix — Task 1

**Report-assisted, human-declared** (see `docs/evals/evaluation-methodology.md`):
the latest `full`-suite eval report suggests a status; a human declares the
final status with a reason; README and the frontend render this same data.
A pass-rate does not threshold itself into "supported" — declaring is an
engineering-judgment act, and the reason column is the graded honesty evidence.

Entry shape (also served as JSON to the frontend):

```json
{
  "domain": "wikipedia.org",
  "task_type": "TC2 search-then-extract",
  "eval": "7/8",
  "declared_status": "unreliable",
  "reason": "Disambiguation pages still misroute the extraction step (case tc2-wiki-004)."
}
```

| Limitation | Evidence | Status |
|---|---|---|
| **D29** — a target that resolves to several elements is narrowed by the page instead of failing the run, in three shapes and no others; the test that decides "these matches are interchangeable" reads an element's `role` attribute falling back to its tag name, not the computed ARIA role, and the test that decides "this task asks for one thing" is a regex over natural language that misses plural asks in both directions | M38 (ADR-026) adds three rungs to `resolve()`, tried only after every tier has had its chance at a unique match, and only for a READING step whose task asks for one thing — all three, including the loosened anchor passes, which sit in the `near` branch and were ungated for one round (PR #42 R7): the step's identity `anchor` reused as a proximity anchor (`resolver-narrows-by-anchor-proximity`), the first match in document order when the matches are interchangeable (`resolver-narrows-identical-matches`), and a `near` anchor matched through typographic quote/dash variants and then by its first 40 characters (`resolver-near-normalises-typography`), that last one gated by `resolver-refuses-plural-on-a-loose-anchor` and `resolver-refuses-a-click-on-a-loose-anchor`. What is NOT gated, deliberately: `near`'s own exact and substring matching, which M6 shipped and which stays available to any step — an anchor the page actually contains is the proximity the plan asked for, and Playwright normalises whitespace inside those two passes itself. The rung is named in the trace step's `note` and wears no `retry_or_recovery` label. Every conjunct of the guard has a case that is red when and only when that conjunct is removed, measured by ablating each one over the whole suite (PR #42 R2/R3 found three of the original five cases passing for reasons unrelated to the guard they claimed to pin): the reading-step conjunct by `resolver-refuses-narrowing-a-click` (two buttons, one accessible name, the same reading, different effects — widen `READS` and the run presses the first), the singular-task conjunct by `resolver-refuses-plural-with-anchor` and `resolver-refuses-plural-wording` (one per rung, since the test gates both) plus one case per phrasing, the role half by `resolver-refuses-mixed-roles` and the text half by `resolver-refuses-different-readings` (same role, different readings, no usable anchor, and the first match in document order is the WRONG user). `l4-shop-duplicate-labels` is NOT one of these pins — three documents claimed it was, and PR #42 R2 falsified that — it keeps its own job, role+name uniqueness breaking and being rescued by relocation | `unsupported` for three named shapes, declared rather than guessed at. (1) **The role test is a tag test.** Two elements with the same tag and different computed ARIA roles — a scope-less `<th>` beside a `<td>` (the shape `near-excludes-its-own-anchor` was built on), an `<a>` with no `href` — read as interchangeable, so the document-order rung may pick between them where a computed-role probe would refuse. No fixture demonstrates it and none is invented here; the upgrade is a computed-role probe per candidate, one `evaluate` per match. (2) **A confidently-wrong identity anchor is answered, not refused.** Rung 1 fires whenever the anchor identifies exactly one place on the page, and an anchor that sits nearer the wrong candidate produces a confident wrong answer where the pre-M38 code produced a loud failure — the accepted risk of ADR-026, visible in the artifact because the trace names the rung, and caught by nothing else in a live run (the same hole D7 and the `trap-*` cases describe: only ground-truth L2 catches a focused wrong answer). (3) **The plural test is a regex over natural language and misses phrasings nobody has probed.** It covers quantifiers, `name/list/give/show (me) the <plural noun>s`, `who are` / `what are`, and the CJK markers 所有/全部/列出/哪些/每個/各個 — one case per phrasing, each watched red first (PR #42 R4). It does not parse grammar: a plural ask phrased outside those shapes (`Which users posted here?`, a plural carried only by an inflected noun, a language whose plural markers are not listed) reaches the rungs and is answered from one match, wrong by omission. Same ceiling and same widening rule as `agent.SCOPE_BLOCK` and `verifier._AGGREGATE` (D21): widen on a phrasing a probe found, never on synonyms nobody has seen. (4) **The plural test fires in both directions, and each has its own case.** The `name/list/give/show the <noun>s` branch is a spelling rule, not a grammar: it excludes `ss` before the final `s` and nothing else. That one exclusion is correct both ways — an English plural of a word ending in `ss` is `-sses`, so no plural carries `ss` immediately before its final s, which is why `the address`, `the business` and `the class` narrow (`resolver-narrows-singular-noun-ending-in-s`, red when the exclusion is removed). `u` and `i` were excluded beside it for one round and no such claim was true of them: `the status` and `the menus` both end in `us`, `the analysis` and `the taxis` both in `is`, so ordinary plurals — menus, taxis, skis, kiwis, gurus, alibis, bikinis, bayous — stopped being recognised and were answered from one match (`resolver-refuses-plural-menus`, red when the exclusion widens past `ss`). Separating those needs a lexicon, so the milestone keeps the OVER-firing deliberately: every singular noun ending in any other letter plus s — `the status`, `the genius`, `the analysis`, `the lens`, `the news` — reads as plural and refuses to narrow. That direction costs a loud `locate` failure; the other costs a confident wrong answer, and the asymmetry is chosen rather than split |
